# Практика 02: Git-конфликт и безопасная отмена

## Цель

Самостоятельно создать конфликт, разрешить его, временно спрятать изменения и
отменить коммит без переписывания общей истории.

> Все действия выполняйте только в своём Fork. В этом учебном сценарии `main`
> изменяется локально специально для создания конфликта.

## Материалы перед заданием

## Задание

1. Создайте `solutions/02-git/story.txt`, добавьте строку и сделайте коммит в
   локальном `main`.
2. Создайте ветку `feature/conflict`.
3. Измените строку в `story.txt` и сделайте коммит.
4. Вернитесь в `main`, измените ту же строку иначе и сделайте коммит.
5. Выполните `git merge feature/conflict`.
6. Изучите конфликт через `git status` и сам файл.
7. Выберите итоговый текст, выполните `git add` и завершите merge-коммитом.
8. Создайте новое незавершённое изменение и спрячьте его через `git stash`.
9. Проверьте `git stash list`, затем верните изменение через `git stash pop`.
10. Создайте тестовый коммит и отмените его через `git revert`.

После основных шагов проверяйте состояние:

```bash
git status
git log --oneline --graph --decorate --all
```

## Результат

В `solutions/02-git/README.md` ответьте:

- почему возник конфликт;
- как он был разрешён;
- чем `revert` отличается от удаления коммита;
- для чего пригодился `stash`.

Не отправляйте учебные изменения из локального `main` в основной репозиторий.
Опубликуйте только ветку своего решения.

# Практика 07: вопросы про REST

## Цель

Закрепить REST как архитектурный стиль, где API проектируется вокруг ресурсов,
HTTP-методов и понятного контракта.

## Задание. Вопросы на понимание

Создайте `solutions/07-rest/rest-questions.md` и ответьте на 10 вопросов. Для
каждого ответа достаточно 2-4 предложений.

1. Почему REST - это не просто "JSON по HTTP"?
2. Что такое ресурс в REST API? Приведите три примера ресурсов.
3. Чем ресурс отличается от его представления?
4. Почему в REST URL обычно лучше описывать существительными, а не глаголами?
5. Какую роль играют HTTP methods в REST API?
6. Что означает stateless и почему это полезно для масштабирования?
7. Что такое идемпотентность? Приведите пример идемпотентного запроса.
8. Почему status codes являются частью REST API-контракта?
9. Зачем API нужен единый формат ошибок?
10. Почему REST endpoint не должен напрямую повторять структуру таблиц в базе
    данных?

## Критерии готовности

- ответы написаны своими словами;
- есть примеры URL ресурсов;
- объяснены resource, representation, stateless и idempotency;
- показано отличие внешнего API-контракта от внутренней модели базы;
- файл оформлен в Markdown.

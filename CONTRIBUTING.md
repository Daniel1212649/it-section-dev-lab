# Contribution Guide

Спасибо за желание улучшить проект.

## Личные решения

Не отправляйте Pull Request с личным решением учебного задания. Выполняйте
задания в своем Fork и делитесь ссылкой в Telegram или GitHub Discussions.

## Какие Pull Requests принимаются

- исправление ошибки или неточности;
- улучшение документации;
- новое практическое задание;
- тесты для существующего кода;
- полезная доработка общего проекта;
- исправление безопасности.

## Что не принимается

- личное решение без изменения общего задания;
- несколько несвязанных изменений в одном PR;
- бинарные файлы и сборочные артефакты;
- `.env`, токены, пароли и другие секреты;
- локальные базы данных;
- настройки IDE;
- автоматически созданные файлы без необходимости;
- изменения без объяснения цели.

## Порядок работы

1. Для большой доработки сначала создайте Issue.
2. Дождитесь согласования идеи с maintainer.
3. Создайте ветку в своем Fork.
4. Сделайте одно логически связанное изменение.
5. Добавьте или обновите тесты и документацию.
6. Откройте Pull Request и заполните шаблон.
7. Ответьте на замечания review.

## Имена веток

```text
docs/improve-linux-task
fix/broken-api-example
feat/add-sql-practice
test/add-storage-tests
```

## Коммиты

Предпочтительный формат:

```text
<type>: <short description>
```

Типы:

```text
feat  новая возможность
fix   исправление
docs  документация
test  тесты
refactor изменение структуры без нового поведения
chore обслуживание репозитория
```

## Перед Pull Request

- убедитесь, что изменение относится к одной задаче;
- проверьте форматирование и тесты;
- удалите временные файлы;
- убедитесь, что нет секретов и персональных данных;
- обновите документацию;
- опишите способ проверки.

Maintainer может закрыть Pull Request, не соответствующий назначению проекта
или этим правилам.
